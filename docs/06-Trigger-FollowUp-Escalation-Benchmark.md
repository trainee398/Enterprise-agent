# 文档 6 · Trigger / Follow-up / Escalation Benchmark

> 文档归属（2026-09-08 整理）：长期企业 Agent 学习与评测草稿，保留原学习状态，不是当前知识库一期的实现说明或验收要求。当前工作见[一期范围记录](00-知识库一期范围与待确认事项.md)。

> 状态：骨架（主体由第 5 课填充）
> 目标：回答"Agent 什么时候应该行动，什么时候应该保持沉默"——降低无效干扰与发现风险同样重要

## 已确立的结论（第 1 课）

- 决策层测试的两个方向缺一不可：should trigger（该出手时出手）与 shouldn't trigger（不该出手时沉默）。
- False Intervention Rate 是主动式 Agent 的头号信任杀手指标：若公司每天 1 万个事件、错误提醒 900 条，Agent 会被全员忽略。
- Forbidden Action 必须用确定性测试全覆盖（如：不得直接向开发人员追责）。

## 待填充大纲

### 1. 场景分类学
- [ ] 触发维度枚举：时间（临期/逾期/停更）、质量（P1 数量/回归失败）、依赖（上游阻塞）、人员（无主任务/休假冲突）、外部（需求变更/客户等待）
- [ ] 每维度的正例/负例/边界（当天到期、95% 完成、刚更新过、负责人在休假……）
- [ ] 对抗用例：数据看似异常但有合理解释（延期说明已填写）

### 2. 用例 Schema 与生成方式
- [ ] 字段：环境快照（任务/人员/依赖/历史打扰记录）/ should_trigger / severity / expected_recipient / expected_action / forbidden_action / 时限要求
- [ ] 合成 + 历史回放两种生成方式

### 3. Follow-up 状态机用例
- [ ] 回复路径全覆盖：按时回复 / 超时不回 / 部分回答 / 换渠道回复 / 回复中甩锅他人（需核实）/ 回复中含注入攻击
- [ ] 防骚扰：催促上限、静默时段、重启后不重复

### 4. Escalation 用例
- [ ] 升级时机（过早/恰当/过晚三档）、升级对象（组织架构变更场景）、证据包完整性清单
- [ ] 措辞合规：归责词汇黑名单

### 5. 指标定义
- [ ] Event Recall / Trigger Precision / Trigger Recall / Action Accuracy / Recipient Accuracy / Escalation Accuracy / False Intervention Rate
- [ ] 指标间权衡：Precision 与 Recall 的业务优先级（宁可漏报低严重度，不可高频误报）
