# 知识库一期原型方向与图片生成提示词

> 整理日期：2026-09-08。当前讨论稿，依据[范围记录](00-知识库一期范围与待确认事项.md)。领导提出“容易上手、先做好一个点”；下述具体切入点和页面方案仍待验证。

## 1. 本轮先展示什么

建议先展示一个点：**打开就能放资料，不用先想怎么分类。**

语雀的个人体验给了一个参考：默认有地方放，之后按需要整理。领导尚未记录确认具体采用默认知识库；本轮原型用它讨论如何减少上传前的选择。

先生成一张首页，围绕上传入口、文案和列表密度做少量对比版本。需要解释完整流程时，再补同一设计的处理中状态和文档编辑页。对比时尽量只改变一个因素，避免几张图同时换布局、功能和风格。

| 原型部分 | 展示重点 |
| --- | --- |
| 首页 | 上传是主要动作，搜索与最近资料承接，默认位置和可见范围能理解 |
| 处理中/失败 | 用户知道发生了什么，以及接下来能做什么 |
| 文档页 | 正文可读可改，保存反馈明确，需要时能核对来源 |

多层目录、建库配置、历史和导出等可按需展开；功能是否一期交付仍看范围确认，不因原型隐藏入口就视为已取消。

## 2. 首页图片生成提示词

以下内容可复制到图片生成工具。生成图用于讨论布局，图中文字或交互仍需人工检查。

---

请设计一张企业内部资料管理工具的高保真桌面网页原型。产品名称为“资料库”。

设计目标只有一个：让第一次使用的人打开页面，就知道如何放入一份资料，不需要教程，也不需要先建立分类体系。

产品接收用户上传的文件，转换成可阅读、可修改的文档。默认归属由系统处理，用户需要整理时再主动操作。当前原型以个人默认位置为示例，并清楚显示“仅自己可见”。

请生成 1600×1000 的完整网页界面，简体中文，正面平视，无设备外壳。

**页面布局**

使用单栏主内容区，内容适度居中，避免多层侧边导航。

顶部左侧是“资料库”，右侧是用户头像和低调的设置入口。

页面最显眼的位置是一个宽敞但不过大的上传区域：

- 主文案：“把资料放进来”
- 辅助文案：“拖入文件，或点击上传。处理完成后即可查看和修改。”
- 主按钮：“上传资料”
- 下方轻量显示：“保存到：我的资料 · 仅自己可见”

接下来是搜索框，提示语“搜索你的资料”，宽度与下方列表一致。

下方为“最近资料”列表，只展示文档标题和最近修改时间，行尾有低调的更多操作按钮。使用四篇示例资料：“项目启动说明”“本周会议记录”“环境配置指南”“接口交付清单”。其中一篇显示“正在转换…”，其余文档正常呈现，不重复显示“成功”标签。点击标题即可打开正文。

“新建空白文档”作为较轻的文字入口，放在最近资料标题旁边。移动和分类放在文档更多操作中，需要时展开。

**视觉要求**

画面简单、清楚、亲切，适合工作繁忙、没有时间学习新工具的人。白色背景、浅灰分隔线、深灰文字，用低饱和绿色强调“上传资料”。字体清晰，字号舒适，留白充分。

上传区域是唯一的主要视觉重点，搜索和列表自然承接。首页聚焦上传、搜索和最近资料。避免统计仪表盘、多层目录树、知识库卡片墙、模板市场、标签填写表单和技术参数，不出现 AI 聊天框或 Agent 工作流。

输出像一个已经可以使用的简洁产品，完整绘制当前页面，不添加宣传海报元素或大段设计说明。

---

提示词里的产品名、个人默认位置和“仅自己可见”是原型示例，不是已确认的产品命名或权限方案。

## 3. 怎么看原型是否有帮助

给首次使用者一份代表性资料，不先解释知识库、目录和转换技术，让其指出上传入口、预计保存位置和可见范围。记录犹豫、误点、求助和误解；静态图只能验证理解，不能证明实际上传或保存成功。

拿到可操作版本后，接着完成“上传 → 打开 → 改一处 → 保存重开 → 找回”。具体记录方法与候选用例见[提测草案](10-知识库一期提测用例草案.md)。

给领导讨论时重点说明：减少了哪些开始前的选择，必要的保存与权限信息是否仍然清楚；界面美观与实际容易上手分别收集反馈。
