## 2. 三条基本业务流程

| 模块 | 当前业务流程 | 本轮结果 |
| --- | --- | --- |
| 知识 | 明确空间和分类 → 创建条目 → 保存标题及正文 → 重开、搜索和维护 → 查看历史或归档 | Markdown 保存重开、标题搜索、同空间移动、历史查看通过；思维导图和甘特图创建重开通过；归档失败 |
| 企业云盘 | 在有权限空间建立文件夹 → 上传 → 预览和下载 → 移动、删除或恢复 | MD/TXT/DOCX 样本通过；一级、二级文件夹及临时文件删除恢复通过 |
| 部门权限 | 建立独立部门 → 员工加入 → 按当前权限使用部门及企业资料 → 随调部门更新访问范围 | 独立部门的访问隔离、企业只读限制和调部门后的权限变化通过；默认部门创建存在 ID 冲突覆盖 |

知识分类与云盘文件夹分别管理各自内容，不因名称相同而关联。已保存内容在分类切换后保持一致，不等于未保存输入、并发编辑等情形也已验证。

## 3. 知识与云盘如何衔接

| 方向 | 已确认结果 |
| --- | --- |
| 云盘 MD/TXT → 知识 | 显式转知识后生成条目，正文与样本文本一致 |
| 云盘 DOCX → 知识 | 创建条目及附件记录成功，但知识正文为空，页面未展示附件；原文件云盘预览正常 |
| 知识 → 云盘 | 本轮 DOCX 导出成功，可预览和下载 |

因此，当前不能概括为“上传即自动转 Markdown”，也不能概括为“知识与云盘完全不通”。已验证的是部分格式的显式转换和一次性导出结果；源文件修改后的自动同步没有验证。

## 4. 部门与权限的理解边界

部门空间承载本部门资料，企业空间承载企业范围资料。本轮普通员工在本部门可以编辑知识和管理云盘文件，在企业空间可读、相关写操作被拒绝；管理员可以创建企业测试知识。

销售员工直接调用接口访问研发知识、历史、搜索和云盘文件均被拒绝。研发员工调到销售部后，原会话立即失去旧部门资料访问权限；调回后恢复。

以上依据独立部门测试。默认创建 `QA_研发部`、`QA_销售部` 时均返回 ID `QA`，导致名称覆盖。已为测试研发部显式指定独立 ID 后再验证隔离，该处理不代表缺陷已修复。不能把部门名称显示为两个不同名字当作已经建立两个独立权限范围。
