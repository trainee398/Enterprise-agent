## UX-01：正文空间小，反向链接继续占用编辑区域

- **复现路径：** QA_研发部 → 知识 → QA_基础回归_20260916 → 打开 `QA_知识回归_20260916_页面保存`。
- **实际表现：** 分类栏旁的正文区域还包含页面标题、知识标题、两行工具栏和底部保存栏。在本轮 1280 × 720 窗口的初始状态下，正文可见高度约 190 像素；编辑内容与外层面板存在嵌套滚动。已保存文档下方显示“反向链接”，即使没有链接也保留说明和空状态。
- **影响：** 输入、选中文本、调整列表以及连续阅读都需要频繁滚动。空反向链接占用纵向布局，使用户更难保持正文上下文。
- **建议：** 正文优先占满剩余高度；提供专注编辑／展开编辑区入口；精简常驻工具栏高度。反向链接默认折叠为“反向链接（数量）”，无链接时收起，主动展开后再显示说明。避免正文和外层面板同时滚动。
- **验收要点：** 保存后不因空反向链接展开而缩小可见正文；同一窗口下明显增加可见正文行数，编辑主要依赖一处滚动；链接仍可主动查看。
- **依据：** 用户反馈，本轮页面确认。没有据此认定内容丢失或保存失败。

## UX-02：查看原件的路径过长，预览排在附件管理区之后

- **复现路径：** 打开 `QA_转知识回归_20260916_docx` → “查看原件附件” → 右侧附件抽屉 → 已关联附件“预览” → 向下滚动 → 阅读预览；需要大面积阅读时再点“全屏预览”。
- **实际表现：** 点击“预览”后，预览位于“从可访问云盘选择”、来源空间、源文件列表和上传操作之后，初始视口看不到预览内容。抽屉宽约 438 像素，预览卡片还要扣除内边距。**现有全屏预览已实际打开，可正常阅读；问题是入口位置和到达路径。**
- **影响：** 用户明明在查看既有附件，却先经过添加附件的操作区，容易误以为预览没有打开；窄窗口也不便阅读 Word。
- **建议：** “查看原件”直接打开大尺寸预览，复用云盘已有的预览窗口；附件管理另设入口。若暂时保留抽屉，至少将预览放在已关联文件下方、点击后自动定位，并默认折叠添加附件区域。
- **验收要点：** 从知识详情一次点击即可看到原件正文，不必滚过附件选择器；全屏入口始终可见，关闭后回到原知识。
- **依据：** 用户反馈，本轮实际点击、滚动及全屏验证。

## UX-03：从搜索结果打开知识后，结果区仍挤占编辑空间

- **复现路径：** 在 QA_研发部搜索完整标题 `QA_转知识回归_20260916_docx` → 点击唯一结果。
- **实际表现：** “搜索结果”标题和结果卡片继续保留在编辑器上方，编辑器被推向下方；标题、附件提示和工具栏进一步占用剩余高度，正文难以在首屏阅读。
- **影响：** 从搜索进入同一份知识，比从分类进入更难阅读和编辑，也不容易判断已经打开详情。
- **建议：** 打开结果后以知识详情占据主内容区，保留紧凑的“返回搜索结果”；返回时恢复关键词和列表位置。或将结果列表收起，不继续占据编辑器上方的大块高度。
- **验收要点：** 搜索进入与分类进入的正文可用面积基本一致；返回结果不必重新搜索。
- **依据：** 本轮页面确认。

## UX-04：附件型知识仍以空正文编辑器为主体

- **复现路径：** 打开上述 DOCX 转入的知识。
- **实际表现：** 页面已说明“此知识以原件附件固定保存，未转换为正文”，但仍显示完整富文本工具栏、空编辑区“开始整理这份知识…”、反向链接及保存栏；原件需另行打开。
- **影响：** 用户容易把空正文理解为导入没有内容，实际文件可读这一事实不够突出。
- **建议：** 附件型知识默认展示文件名、类型和大尺寸原件预览；需要补充文字时再展开备注／正文编辑。文字型知识继续以正文为主。此建议不要求新增 DOCX 转 Markdown 能力。
- **验收要点：** 打开附件型知识能直接理解内容保存在哪里，并立即阅读；不以空编辑器作为首要视觉内容。
- **依据：** 本轮页面确认；当前附件保存方式本身不是转换故障。

## UI-05：搜索结果分类显示错误

- **前置条件：** `QA_转知识回归_20260916_docx` 属于 `QA_基础回归_20260916`。
- **复现步骤：** 在当前部门搜索该完整标题，查看结果卡片，再打开结果。
- **预期结果：** 结果卡片显示该知识的实际分类，与详情一致。
- **实际结果：** 卡片显示“分类未提供 · 当前修订”，而打开后的编辑区明确显示 `/QA_基础回归_20260916`。
- **影响：** 搜索结果不能正确帮助用户识别资料归属，降低整理和同名文档辨识效率。搜索与打开仍成功，不阻断流程。
- **建议与验收：** 统一搜索结果和详情的分类展示；对本轮样本搜索后应显示正确分类。具体是返回字段还是前端映射问题，本轮未定位。
- **状态：** 本轮页面已复现，待修正。等级 P2，非阻塞。

## UX-06：技术信息占据文件列表和预览的主要位置

- **复现路径：** QA_研发部 → 企业云盘 → `QA_基础回归_20260916` → 预览 `QA_云盘回归_20260916.docx`；知识附件预览也有相同表现。
- **实际表现：** 文件列表和附件卡片展示很长的 DOCX MIME 类型；预览正文顶部用一长串内部编号作为大标题，并显示英文 `Word document extracted preview`。这不是用户上传时的文件名。
- **影响：** 占用阅读空间，用户还需辨别内部编号与真实标题；窄抽屉下尤为明显。
- **建议：** 列表优先显示文件名、Word／文本等易懂类型、大小与时间；预览用文件名或原文标题。技术编号、MIME 和实现说明移至可展开详情。保留必要的“原件副本，后续不随云盘原文件更新”说明，但不抢占阅读区。
- **验收要点：** 预览首屏先看到可辨识的标题和内容，不出现内部编号大标题；普通列表不依赖阅读 MIME 判断格式。
- **依据：** 本轮云盘及知识附件页面均确认。

## UX-07：云盘文件操作列在常规窗口下拥挤换行

- **复现路径：** 企业云盘 → `QA_基础回归_20260916`，在 1280 × 720 窗口查看文件列表。
- **实际表现：** 文件名、格式、大小、更新时间和行尾操作共用一行；“预览”“下载”被挤成逐字换行，长格式名称被截断。
- **影响：** 操作不易快速识别，文件行的信息层次混乱。按钮功能未据此判定异常。
- **建议：** 为操作列保留最小宽度并禁止按钮文字断行；将次要操作放入“更多”，配合缩短文件类型显示。文件名优先保留可读宽度。
- **验收要点：** 在该窗口尺寸下操作名称不拆字，预览和下载入口稳定可见，长文件名可查看完整名称。
- **依据：** 本轮页面确认。

## UX-08：新建与导入需要先离开“全部知识”选择分类

- **复现路径：** 活动部门 → 知识 → 全部知识或搜索状态。
- **实际表现：** “新建知识”“从云盘导入”禁用，提示先选择左侧分类；用户必须先改变浏览位置，才能开始创建。
- **影响：** 想先写内容或导入文件的用户需要额外理解分类前置规则。基础创建仍可完成。
- **建议：** 新建／导入时允许在同一流程选择已有分类；已经选中分类时默认带入。先减少开始操作前的跳转，不要求本轮改造完整创建流程。
- **验收要点：** 从全部知识也能发起创建或导入，并在提交前明确选择归属分类。
- **依据：** 本轮禁用入口和提示已确认；创建步骤较多亦为用户此前反馈。

## UX-09：草稿自动保存与保存修订的状态不够直观

- **场景与实际表现：** 当日基础回归编辑时出现“草稿已自动保存／尚未形成修订”，显式操作为“保存修订”；保存后的页面显示“已保存为修订／最近修订”。两种保存状态均使用“保存”概念。
- **影响：** 用户需要理解草稿和正式修订的区别，容易不确定离开后能找回什么、他人看到哪一版。这是理解成本，本轮没有发现由此造成的数据丢失。
- **建议：** 用明确状态区分“有未提交修改（草稿已暂存）”与“已保存，时间”；在必要位置简短说明草稿的可见范围及恢复方式。具体文案须与实际业务规则一致。
- **验收要点：** 修改后、草稿暂存后、显式保存后三种状态清晰区分；离开页面提示与实际恢复行为一致。
- **依据：** [当日页面观察记录](../test-datasets/runs/2026-09-16-retirement/页面观察记录.json)及本轮保存后页面；本轮体验检查没有再次修改正文。

## UX-10：只读空空间仍提示用户创建知识

- **复现路径：** 工作区选择“运维修部（历史只读空间）” → 知识，等待加载完成。
- **实际表现：** 顶部明确退役只读，左侧也显示“当前权限为只读，暂无可见分类”，但主区域仍提示“当前空间暂无可见知识。请先创建一个分类，再新建知识。”相关按钮实际禁用。
- **影响：** 用户收到无法执行的引导，容易误以为按钮故障。不是只读权限失效。
- **建议：** 只读空状态显示“当前空间暂无可查看的知识”；退役空间可补充“历史只读，不支持新增”。创建引导仅在有写权限时显示。
- **验收要点：** 只读空间的提示不再要求新增；可写空间仍保留创建引导。
- **依据：** 本轮加载完成后的页面确认。

## UX-11：左侧对话与工作台导航延后统一处理

- **本轮观察：** 活动部门与历史只读部门混排，较长测试部门名称在固定宽度侧栏被截断；空间增多时需要滚动查找。
- **影响：** 导航辨识和寻找效率一般，不阻断基础功能。退役部门作为历史只读空间继续展示符合当前规则，不记为删除残留 Bug。
- **处理意见：** 按用户要求降低优先级，随左侧对话／工作台后续整体调整再处理。届时再统一考虑历史空间分组、收起及长名称展示。本轮不展开对话功能测试，也不单独推进该区域重做。
- **依据：** 本轮导航观察和用户明确的后续调整计划。

## 建议先安排的前端工作

1. 优先扩展正文编辑空间，折叠空反向链接，去掉搜索结果对详情的持续挤占。
2. 让“查看原件”直接进入已有大尺寸预览，附件型知识突出原件内容。
3. 顺手修正搜索分类、只读提示以及文件技术信息展示；云盘操作列调整不必等待整体导航重做。

保存文案、创建入口随后调整；左侧对话和工作台保持低优先级。前端交互后续仍会调整，本清单是问题与验收方向记录，不固定最终页面方案。
