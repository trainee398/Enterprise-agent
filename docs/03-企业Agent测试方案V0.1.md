> 目标：可直接用于项目测试计划评审的方案文档

## 已确立的结论（第 1 课）

- 测试对象不是"Question → Answer"，而是完整链路：
  Data → Event → Retrieval → Fact → Derived Fact → Assessment → Decision → Action → Follow-up → Escalation
- 每一层单独可测、单独有验收标准；链路级缺陷需要按层定位（参考第 1 课自检题 Q4 的定位顺序：审计日志回放 → 决策记录 → 评估证据 → 推导计算 → 原始事实 → 源数据）。
- 分层判定方式：确定性代码判定优先（推导、护栏、权限、收件人），检索用 IR 指标，主观质量用 LLM-as-Judge + 人工抽检校准。

### 2. 分层测试策略
- [x] L1 接入（U2b 口诀，不当工程作业）：
  - 对账：源条数 vs 入库条数（防分页/限流丢页）
  - 延迟 SLA：源变更到可检索的时延
  - 删除传播：源删/归档后不可检索（幽灵数据）
  - ACL 映射：源权限是否随记录入库，检索/生成/发送三处是否仍执行
- [x] L2a 检索（U2a 契约初稿；权限维留给 U2b）：
  - 测试对象拆六段：解析 → 切块+元数据 → 双索引 → 检索 → 重排 → 带引用生成。每段有输入/输出，缺陷先归层再开单。
  - 解析：代表性文档集；关键句/表格格能否还原；代码或人工，不用 Judge 判「数字在不在」。
  - 检索：`retrieval-golden`（问法 → 必须命中的 chunk / 原文）；Precision@K、Recall@K、NDCG；先看 Top-K 再看最终答案，避免生成掩盖检索错误。
  - 生成：接地与引用回跳可代码抽检；语气/覆盖用 Rubric + 人工；库中无依据时应拒答。
  - 权限感知检索、删除传播、Connector 对账：U2b。
