## 1. 产品定位

- 不是"员工提问 → 回答"的企业 Chatbot，而是 Proactive / Autonomous / Event-driven 的企业 Agent。
- 核心工作方式是持续运行的闭环：**感知 → 事实 → 判断 → 行动 → 跟进 → 升级**，全程留痕可审计。
- 与行业叙事同构：ServiceNow Sense–Decide–Act、OODA 循环。"主动监控 + 提醒"在 2026 年已是行业标配能力（详见文档 7），我们的差异化在跨系统证据链、核实式追问、防骚扰策略与审慎升级。

## 2. 分层架构

```
┌────────────────────────────────────────────────────────────┐
│  LX 治理层（横切所有层）：权限 · 审计 · 防注入 · HITL · 回滚      │
└────────────────────────────────────────────────────────────┘
 L0 数据源      Jira / 飞书 / Notion / 数据库 / BI / 邮件 / 会议纪要
 L1 接入层      Connector：数据 + 权限(ACL) + 变更事件 持续同步
    ├─ L2a 知识索引（非结构化）Parser → Chunking → Embedding → 混合检索
    └─ L2b 数据查询（结构化）  Semantic Layer → 指标口径 → SQL/API
 L3 事件感知    Webhook + 定时扫描 + 规则监测（主动性的来源）
 L4 事实层      跨系统证据库：来源/权威度/时间/权限/溯源
 L5 推导层      确定性规则计算——代码算，不是 LLM 算
 L6 评估        带证据的判断（结论 + 严重度 + 证据引用）
 L7 决策        LLM 提议 + 策略引擎把关（频率/静默/HITL）
 L8 行动        工具调用：参数对、人对、全程留痕
 L9 跟进        持久状态机：等回复 → 核实说法 → 扩展事实链
 L10 升级       带证据包升级：只陈述事实，不归责
 （行动与回复成为新事件，回流 L3，形成闭环）
```

每层的输入/输出/典型错误/测试要点详见 `notes/第01课-企业主动式Agent知识地图.md` 第 3 节。

## 3. 关键架构决策



### 3.1 数据双路径（而非单一 RAG 管道）

- 非结构化知识（文档/消息/纪要）走 L2a：解析 → 切块 → 向量 + BM25 混合检索。
- 结构化数字（指标/进度/金额）走 L2b：Semantic Layer 定义口径 → SQL/API 精确查询。
- 理由：数字被向量化后靠"语义相似"召回，口径、新鲜度、精确性全部失控。数字靠查，不靠猜。



### 3.2 事件感知作为一等公民

- 三种机制互补：Webhook（有变化就推）、定时扫描（兜住"什么都没发生"型异常）、规则监测（阈值）。
- 没有这一层，产品退化为被动问答系统。



### 3.3 Fact Layer 是设计模式，不是采购件

- 定义：跨系统、带来源/权威度/时间/权限/溯源的结构化事实断言库，是 Agent 判断的证据库。
- 行业最接近的对应物：ServiceNow Context Engine、Glean Knowledge Graph、Palantir Ontology。
- 落地策略：从项目、指标、人员三类事实起步，按用例扩展，不一上来事实化全公司。
- 注意与数仓 Fact Table（Kimball 维度建模术语）区分，同名不同义。



### 3.4 推导用代码，判断用模型

- Derived Fact（逾期天数、停更天数）由确定性规则计算，可单测、可复现。
- Assessment（延期风险及严重度）由 LLM 结合上下文生成，但必须携带 fact_id 证据引用。



### 3.5 跟进与升级由持久状态机承载

- 跨天存活：记住问过谁、等谁回、催过几次；服务重启不丢状态、不重复打扰。
- LLM 只在判断点介入（理解回复、决定下一步调查方向）。



### 3.6 治理横切每一层

- 权限三处执行：检索时、生成时、发送时。
- 员工回复视为不可信输入（Prompt Injection 攻击面）。
- 审计日志全链路：任一 Agent 行为可回放解释。
- 责任边界：AI 可以发现/查询/提醒/询问/记录/汇总/建议/升级；涉及绩效、处罚、责任归属的判断保留 Human-in-the-loop。



## 4. 事实与判断的严格边界

```
Fact → Derived Fact → Assessment → Causal Attribution → Responsibility Attribution
                                                    ↑
                                        AI 到此为止，此线以上 HITL
```

- 转述内容单独立档："张三说 X"中，"说过"是事实，"X 是否为真"是待核实主张。
- Agent 收到单方解释必须核实（查依赖、查对方任务状态、查需求变更记录），再更新评估。
