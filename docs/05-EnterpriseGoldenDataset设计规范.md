# 文档 5 · Enterprise Golden Dataset 设计规范

> 状态：骨架（主体由第 6 课填充）
> 目标：解决"我觉得可以、别人觉得不可以"的主观分歧，建立客观测试标准

## 要回答的核心问题

1. Golden Dataset 覆盖哪些环节？（检索 / 事实抽取 / 评估 / 触发 / 跟进 / 升级——每环节独立成集）
2. Ground Truth 从哪来？谁有资格定义？（业务权威源、领域专家、多人标注仲裁）
3. 如何把"我感觉不错"变成 0/1 判断或 0–4 评分？（Rubric 设计规范）
4. 多人标注不一致怎么办？（Inter-Annotator Agreement 度量与仲裁流程）
5. 数据集如何演进？（版本管理、线上 bad case 回流、防止过拟合评测集）

### 2. 用例 Schema
- [ ] 统一字段：case_id / 场景描述 / 输入数据快照 / 期望输出 / 判定方式 / 严重度 / 标注人 / 版本
- [ ] 触发类用例增加：should_trigger / expected_action / forbidden_action（沿用第 1 课 Case 001–003 模式）

### 3. Ground Truth 治理
- [ ] 分级授权：数值类以权威系统为准；判断类由领域专家小组认定；争议升级机制
- [ ] 标注指南编写规范
- [ ] IAA 门槛（如 Cohen's Kappa ≥ 0.7 才可入集）与不一致仲裁流程

### 4. Rubric 规范
- [ ] 0/1 判断优先；不得已才用 0–4 分档
- [ ] 每档必须有可执行描述与示例（好/坏对照）
- [ ] 禁止出现"较好""基本合理"等不可操作措辞

### 5. 维护机制
- [ ] 版本化与变更评审
- [ ] 线上 bad case 回流入集流程
- [ ] 评测集污染防护（训练/Prompt 中不得引用评测集内容）
