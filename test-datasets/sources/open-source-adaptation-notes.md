# 开源资源适配笔记

> 后续方法资料（2026-09-08）：本文保留开源/RAG 预研内容，不是当前文档管理一期的必做任务，也不代表已下载官方数据或通过产品测试。当前范围见[范围记录](../../docs/00-知识库一期范围与待确认事项.md)。

本文件只提取测试设计方法，不复制外部数据。正式下载前仍需在 `registry.md` 补充版本、许可证、原始 ID 和哈希。

## BEIR / MTEB：检索层

- 保留 `query -> relevant document/chunk` 的 qrels 关系。
- 先计算 Recall@K，再看排序质量；不要只看最终回答。
- 将公开数据中的 document ID 映射到本项目的 `doc_id`，不要覆盖原始 ID。
- 企业 V1 额外加入编号、人名、版本和相似项目干扰。

## DocLayNet / PubTables：解析层

- 重点借鉴标题、段落、表格、页眉页脚和阅读顺序这些结构标签。
- 转成产品真值时，必须保留原文片段、标题路径、页码或表格行列关系。
- 如果 V1 不支持扫描 PDF/OCR，不把 DocVQA 的视觉问答分数纳入发布门槛。

## RAGTruth / RGB / RAGBench：回答可信度

- 将答案拆成断言，逐条绑定 `required_evidence`。
- 分开判断事实值、上下文接地、引用支撑和拒答/不确定性。
- 无答案、干扰上下文、反事实内容应作为独立 case，不与普通问答混算。

## CRUD-RAG：生命周期

- 把 Create、Update、Delete 传播作为独立测试轴。
- 对每次更新记录旧值、新值、生效时间和索引可见时间。
- 删除后查询仍返回旧内容时，应记录为索引清理或缓存失效问题，而不是回答措辞问题。

## 当前落地结论

本轮先使用 `corpus/` 的受控文档跑通产品链路；开源资源仅用于后续专项校准。这样可以把发现的问题定位到 Parser、Chunk、Embedding、Retrieval 或 Agent，而不是混入外部语料分布差异。
